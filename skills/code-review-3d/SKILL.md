# 代码审查三维检查法（Code Review 3D）

## 概述

从**三个维度**并行审查代码，逐条输出结构化中文报告。任何一次审查都必须是三维全覆盖，不允许只报表面问题。

## 维度一：整洁性（Cleanliness）

| 检查项 | 关注点 |
|--------|--------|
| 命名 | 变量 / 函数 / 类 / 常量命名是否清晰、符合语义（忌 `tmp`、`x1`、`data` 等无意义命名） |
| 重复 | 重复代码块、复制粘贴逻辑、可抽取的公共函数 / 常量 |
| 复杂度 | 过长函数（建议 < 50 行）、过深嵌套（建议 < 3 层）、圈复杂度、魔法数字 |

## 维度二：可用性（Usability）

| 检查项 | 关注点 |
|--------|--------|
| 边界 | 空输入 / 空列表、单元素、极值（最大 / 最小）、负数、超长输入、并发边界 |
| 异常 | 异常处理是否完备、错误信息是否可理解、失败是否静默吞掉 |
| 契约 | 接口文档、前置条件 / 后置条件、返回值约定、参数校验、缺省行为 |

## 维度三：代码质量（Code Quality）

| 检查项 | 关注点 |
|--------|--------|
| 类型 | 类型使用是否安全、隐式转换、弱类型误用、`Any` / `object` 滥用 |
| 隐患 | 潜在缺陷、安全漏洞（注入 / 越权 / 敏感信息）、资源泄漏（文件 / 连接 / 内存）、并发竞态 |
| 可测性 | 代码是否易于测试、依赖是否可注入、是否有副作用、测试覆盖盲区 |

## 严重级别

| 级别 | 含义 | 处理要求 |
|------|------|---------|
| **阻断**（Blocker） | 导致错误结果 / 安全问题 / 无法交付 | 必须修复 |
| **警告**（Warning） | 潜在缺陷或明显不良实践 | 应当修复 |
| **提示**（Suggestion） | 改进建议 / 风格问题 | 可选 |

## 输出格式（中文结构化报告）

每条发现必须包含：**位置（文件:行号）→ 维度 → 严重级别 → 问题描述 → 修复建议**。

```markdown
【审查报告】<文件名 / 模块名>

## 维度一：整洁性
- `src/foo.py:42` | 警告 | 变量名 `tmp` 语义不明 | 建议：改为 `user_count`

## 维度二：可用性
- `src/foo.py:15` | 阻断 | 空列表输入会静默返回 0 | 建议：空输入抛 `ValueError`

## 维度三：代码质量
- `src/foo.py:78` | 提示 | 资源未用 `with` 关闭 | 建议：改用上下文管理器
```
